# 08 · 交付、任务切片与验收

## 1. 验收总原则

**假模型只能证明接线，不能作为模型相关里程碑的验收证据。** 这条是硬规则：M1–M5 的出口条件必须有真实模型、真实观察、可复核的记录。

每个验收证据必须包含：

```text
环境：      隔离 fixture 名称与部署版本
配置版本：   config_revision + 相关对象 revision
输入：      脱敏后的请求体或考试申请
ID：        x-request-id、x-ai-request-id、exam_run_id（按需）
账本：      预占/结算前后的 available / reserved / charged
观察：      独立观察到的结果（不是"接口返回 200"）
失败项：    未通过的项记录在案——不得标完成
```

"接口返回成功"**不是**结果验证。

### 2.1 T0 离线基线检查

`scripts/gateway-v2-baseline.py` 在内存 SQLite 中按文件名顺序重放现有迁移，输出表、列、外键、索引、触发器以及迁移/合约源文件的 SHA-256。它不连接部署中的 D1，不读取真实账户、令牌或渠道密钥，也不执行 PG 迁移。

```sh
python3 -m unittest discover -s scripts/testing -p 'test_gateway_v2_baseline.py' -v
python3 scripts/gateway-v2-baseline.py --write /tmp/hezuo-gateway-v2-baseline.json
python3 scripts/gateway-v2-baseline.py --check /tmp/hezuo-gateway-v2-baseline.json
```

基线检查通过只证明迁移可离线重放、源码与结构未漂移，不代表部署 schema 已核对、迁移映射已签署或 T0/T1 已验收。当前未签署表与身份命名冲突见 [04 §5](04-data-model.md#5-迁移映射d1sqlite--pg)。基线 JSON 应在映射评审时留存，不能在检查失败后直接重生成以绕过评审。


## 3. M1 验收（上游与路由）

| 场景 | 判据 |
| --- | --- |
| 主渠道返回 5xx | 自动切到备用；用户只被扣**一次**；`request_attempt` 有 2 行且第 1 行 `outcome=retryable_error` |
| 主渠道返回 429 | 同上，第 1 行 `status_code=429` |
| 首字节前连接超时 | 切换；不产生额外预占 |
| 已写出后断流 | **不重试**；按已收用量结算；`request_attempt` 只有 1 行 |
| 400 类请求错误 | **不重试**；不切换 |
| 3 个候选全失败 | 释放全部预占，`settled` + `charged=0` + `no_successful_attempt` |
| 能力过滤 | 带图片请求排除无 vision 成员；被排除成员**不写** `request_attempt` |
| 全部尝试失败的成本 | 只进 `retry_loss` 指标，不进用户流水 |
| 密钥 401 | 该密钥 `disabled` + 告警；其他密钥继续服务 |
| 手动 disabled | 自动恢复流程**不改动**它 |
| 冷却恢复 | 只放行 1 个探测（并发 5 个请求只应通过 1 个） |
| 会话粘滞 | 同一 `x-hezuo-conversation-id` 连续 3 次命中同一 `(channel,key)` |
| 配置热生效 | 改配置后 5 秒内 relay 使用新配置；已预占请求用旧快照 |

## 4. M2 验收（计费）

| 场景 | 判据 |
| --- | --- |
| 03 算例 A | 23,800,000,000 → 52,360,000 微积分，**逐位一致** |
| 03 算例 B | 预占 183,876,000；`worstIn = 2,500,000` |
| 03 算例 C | 退差 131,516,000 |
| 03 算例 D | 保守口径 99,000,000，`cost_status=conservative` |
| 03 算例 E | 非补贴组被抬回 22,000；补贴组 21,120 且有 `subsidy_audit` |
| 03 算例 F | 组预占 6,548,166,452；实际结算后退还差额 |
| 03 算例 G | `input=272,000` 用 longRates，`271,999` 用 base |
| 03 算例 H | 极端策略保存被 `billing_price_limit` 拒绝 |
| 03 算例 I | 恒等式成立 |
| 1000 并发 | 无负余额；`available + reserved` 恒等式成立；无重复扣费 |
| 同幂等键并发 | 只产生 1 个 `ai_request`；后到者拿同一 ID |
| 同 key 不同 body | `409 idempotency_key_reuse` |
| 重复结算 | 第二次返回 `noop`，不改金额 |
| `review` 状态再结算 | `request_in_review` 异常，不重复扣 |
| 余额不足补扣 | 扣到 0，`state=review`，`usage_exceeds_reservation` |
| 人工结算超收 | `review_settle_not_downward` 拒绝 |
| 老客户端联调 | 未知 `kind` 不崩溃；新错误码能降级 |

## 5. M3 验收（混合与 newapi）

| 场景 | 判据 |
| --- | --- |
| 嵌套组（深度 3） | 正常选路 |
| 深度 4 | `400 route_depth_exceeded` |
| 成环 | `400 route_cycle` |
| `weighted` 试算 | 同 `simulatedRequestId` 复现同一选择；不同 ID 分布接近权重 |
| passthrough 计价 | 用实际成员价格结算，不是组价 |
| passthrough 预占 | 取最贵候选 |
| `fixed` 组 | 成功即扣固定价，不看 token；不参与倍率控制器 |
| `cost` 策略 | 选成本最低的可满足成员 |
| `latency` 策略 | 样本 < 20 的成员排最后 |
| `newapi` 同步 | 返回建议值，**不写入生效配置**；确认后才生效 |
| 同步部分失败 | 已成功部分保留；失败部分单独报告 |
| 并发 revision 冲突 | `409 revision_conflict` + `currentRevision` |
| 换 baseUrl 不带 key | `400 key_required_on_url_change` |
| 试算一致性 | 后台试算结果与实际选路一致（同模拟 ID） |

## 6. M4 验收（Studio）

| 场景 | 判据 |
| --- | --- |
| 真实模型跑通 | 沙箱内用真实模型完成一个含工具调用的任务；trace 有实际模型 ID |
| 沙箱网络 | 访问非白名单域名被拒；DNS/IP/重定向/IPv6 四种绕过全部失败 |
| 宿主访问 | 读 `/etc/passwd`、宿主 home、Podman socket 全部失败 |
| 路径穿越 | `../` 与越界符号链接被拒 |
| 令牌范围 | 沙箱令牌调 `/v1/studio/*` 或 `/v1/operator/*` 返回 401/403 |
| 令牌过期 | 会话结束后旧令牌立即失效 |
| 资源限制 | cgroup 生效：超内存/超 PID 被 kill，不影响其他会话 |
| 取消与超时 | 容器停止、卷回收、令牌撤销，有证据 |
| 清理失败 | 记录 + 告警，**不谎报成功** |
| `bot_hash` | 改 `soul.md` 变；改 `tests/` 不变；改 `price` 不变；改 `permissions` 变 |
| 版本不可变 | 尝试改 `bot_hash`/`package_ref` 被数据库拒绝 |
| 跨作者访问 | 猜别人 bot id → 404 |
| 模型对比 | 2–5 模型并行，总成本不超会话预算 |

## 7. M5 验收（考试与市场）

| 场景 | 判据 |
| --- | --- |
| 一 Bot 两模型 | 各自独立一场、独立出分、独立 listing |
| 抽样 | 公开 20% / 保密 80%；保密库 ≥ 抽样量 3 倍 |
| k=3 | 每题 3 次不同变体；结果按 `(run,case,variant,run_no)` 唯一 |
| 闸门 | 越权 Bot 直接 `failed`，即使总分很高 |
| 硬编码对抗 | 写死公开题答案的 Bot 在保密题失分或被抓抄袭 |
| 越权对抗 | 读宿主文件的 Bot 被闸门拦下 |
| 预算 | 并行题目合计不突破 `max_cost_points`；到限 `budget_exhausted` 且判不通过 |
| rubric 分歧 | 两次相差 > 2 分时加评第 3 次；仍分歧取保守分并标记 |
| 评分模型隔离 | rubric 模型 ≠ 被考模型 |
| 成绩身份 | 改 `soul.md` → 成绩失效；改 slug → 不失效；改渠道成本价 → 失效 |
| 宽限 | 失效后 7 天内标 `stale` 仍展示；第 8 天变 `unverified` |
| 晚到结果 | 旧版本考试结果不覆盖新版本 listing |
| 场次限制 | 同 Bot 同模型第 4 场被拒；基础设施失败不计场次 |
| 举报 | 3 条举报触发 `pending_review`；1 条 safety 举报立即下架 |
| 审核优先 | 被封禁作者重考及格**不能**恢复 |
| 安装 | 下载 URL 5 分钟过期；权限弹窗列出工具与网络 |
| 市场筛选 | 按模型只出 verified；不带模型显示未验证 |
| 开张条件 | 07 §12 的 7 条全部满足 |

## 8. 迁移验收（M0/M1 之间）

| 步骤 | 判据 |
| --- | --- |
| 导出 | D1 全表行数与摘要记录 |

## 9. 放行门禁

每个里程碑按此顺序，任一失败即停：

```text
1. 安全与账本检查     → 余额、恒等式、越权、密钥泄露
2. 协议兼容          → 老客户端不改代码能用
3. 真实模型端到端    → 真模型、真工具、真观察
4. 迁移与恢复演练    → 备份能恢复，不是"备份完成"
5. 受控灰度          → 内部 → 5% → 25% → 100%，每档 ≥ 24 小时
6. 扩量
```

灰度期监控：

| 指标 | 停止条件 |
| --- | --- |
| `billing_identity_violations` | > 0 |
| 负余额出现 | 任意一次 |
| 重复扣费 | 任意一次 |
| `review` 占比 | > 10% 持续 15 分钟 |
| 凭据泄露 / 沙箱越权 | 任意一次 |
| `outbox` 最老记录 | > 5 分钟 |

安全事件：**先停受影响入口并保全脱敏证据**，不擅自恢复流量。

## 10. 测试矩阵

| 类别 | 必测 | 判据 |
| --- | --- | --- |
| 计价 | 03 的 A–I 九个算例 | 逐位一致 |
| 整数安全 | 非负、上限、溢出、舍入顺序 | 越界即报错，不截断 |
| 并发 | 1000 并发预占；同 key 竞争；重复结算；退款重放 | 无负余额、无重复扣费、恒等式成立 |
| 崩溃恢复 | 结算提交前/后崩溃 | 前：可重入；后：只查结果不重扣 |
| 路由 | 连接失败/首字节超时/429/5xx/额度耗尽/400/拒绝/取消/心跳后断流/3 次边界 | 只在允许边界切换 |
| 配置 | 能力过滤、粘滞续期与破坏、无候选、深度/环、并发 revision、通知丢失、换址密钥 | 过滤不计失败；旧请求不追溯 |
| 授权 | 跨作者/跨账户 id 猜测、模型 scope、运营权限、下载/trace、日志审计 | 不越权；无密钥、无上游地址、无隐藏题 |
| 沙箱 | 非白名单网络、DNS/IP/重定向绕过、宿主目录/socket、路径穿越、令牌过期、取消/超时/崩溃 | 无越权；资源限制生效；回收有证据 |
| 考试 | 抽样、hidden 规模、k=3、权重、闸门、rubric 双评、预算/场次、重复队列 | 不改原标准；评分失败/预算不足不通过 |
| 市场 | 双模型独立出分、各类失效、7 天宽限、余额不足、审核优先 | 旧结果不覆盖新身份 |
| 运维 | 导入计数/恒等式、密钥恢复、在途接管、Redis/对象存储故障、回退边界 | 校验失败不切换；新旧不双写 |

## 11. 本文档集的验证状态

**必须诚实记录**：

| 项目 | 状态 |
| --- | --- |
| `schema.sql` 语法与结构 | **仅静态校验**（括号/引号/$$ 平衡、41 表、37 索引、24 触发器、12 函数、外键目标、GRANT 签名一致、关键不变量存在性）。**未在真实 PostgreSQL 上执行过。** |
| 计费算例 A–I | **已用 Node BigInt 脚本逐位复算**，与 `task-billing.ts` 语义对齐 |
| OpenAPI 骨架 | 结构自检通过；**未用真实校验器验证** |
| 一切运行时行为 | **未实现、未测试、未部署** |

M0 的第一个动作必须是：在真实 PostgreSQL 16 上执行 `schema.sql`，并把结果记录进来。任何静态检查都不能替代这一步。
